Operations Intelligence

El problema. Una empresa de distribución gestiona miles de pedidos, pero la información está repartida y nadie tiene claro dónde se pierden las entregas a tiempo.

Lo que hace este proyecto. Parte de una tabla de 3.000 pedidos y responde a tres preguntas: ¿dónde fallan las entregas?, ¿por qué? y ¿qué se podría hacer? Incluye un panel interactivo, las consultas SQL que lo respaldan y una validación de que los números son correctos.

Todos los datos son sintéticos: los generé con un script de Python para este proyecto. Algunos patrones están introducidos a propósito para poder demostrar el método, así que las conclusiones ilustran cómo analizar un caso, no describen ninguna empresa real. Es un proyecto personal, no experiencia laboral.

Tecnología. Python (generación de datos, análisis y validación) · SQL sobre SQLite (consultas) · JavaScript (panel interactivo). Todavía no incluye un dashboard en Power BI.

    Consultas SQL

    Las consultas están en queries.sql y se ejecutan sobre SQLite con analysis.py. Lo que ves aquí es el texto exacto de cada consulta y el resultado real que devolvió. Uso agregaciones con CASE WHEN, JOIN, GROUP BY, una CTE y una función de ventana. Estoy en formación en SQL, y este proyecto es parte de ese aprendizaje.

    Validación: ¿son correctos los indicadores?

    Cada indicador clave se calcula tres veces por caminos distintos: en esta página con JavaScript, con SQL y con Python puro. Si alguno no coincidiera, analysis.py se detendría con un error.

      Solo necesita Python 3; no hay que instalar nada más.

      Cómo se calculan los indicadores

      Entrega a tiempo
      Pedido «Entregado» cuya fecha de entrega es igual o anterior a la fecha prometida. El porcentaje se calcula sobre los pedidos entregados.
      Retraso medio
      Media de días de retraso solo de las entregas que llegaron tarde, para que no se diluya con las puntuales.
      Coste medio
      Media del coste de los pedidos, sin contar los cancelados.
      Pedidos en tránsito y cancelados
      Cuentan como pedidos, pero no entran en el cumplimiento porque no tienen entrega.
      Limitaciones
      Los datos son simulados y tienen patrones introducidos a propósito (ruta Sur, almacén Centro B y campaña de noviembre-diciembre), por lo que encontrarlos no es un hallazgo real, sino la comprobación de que el método los detecta. El análisis de causas es descriptivo: compara grupos, pero no demuestra causalidad.
